# Module 1 分析方法与自动结论规则（M1_ANALYSIS）

本文说明 Module 1 的时间范围解析、三张时间分析图的统计方法、自动结论（Insights）的判定规则、
ACF 周期检测方法与局限性。所有数值均由后端根据当前选择的真实数据计算，前端只负责展示。

---

## 1. 分析时间范围（Analysis Time Range）

### 1.1 输入方式

| 方式 | 位置 | 说明 |
|---|---|---|
| 日期时间 | 左侧主面板 | `Start Date & Time` / `End Date & Time`，格式 `YYYY-MM-DD HH:mm:ss`，**闭区间** |
| 索引 | Advanced Settings | `Start Index` + `Window Points`（按重采样后的时间点数计） |

两种方式**双向同步**：

* 改日期 → 后端解析为 `start_index / end_index`，返回后自动回填高级索引；
* 改索引 → 后端解析为真实时间，返回后自动回填日期；
* 发起请求时只使用“最后一次编辑的那一侧”作为权威输入（`lastEdit`），避免两边互相覆盖。

### 1.2 解析算法（`services/time_range.py`）

1. 取该数据源在目标分辨率下的时间轴（桶起始时间，`resample_axis`，带缓存）。
2. 把日期字符串按源数据的“朴素本地时间”约定解析为 epoch 秒（与存储序列一致，不做隐式时区转换）。
3. `left = searchsorted(axis, start)`，`right = searchsorted(axis, end, side='right')`，
   得到 `[left, right)` 的点索引区间。因此**开始与结束时刻都包含在内**。
4. 返回：实际起点、最后一个观测、点数、时间跨度、采样间隔、数据边界、是否被截断。

### 1.3 分辨率与点数换算

重采样只改变时间桶的粗细，不改变真实时间范围：

| 数据源 | 原生间隔 | 1 天 | 7 天 |
|---|---:|---:|---:|
| Milano / Trentino | 10 分钟 | 144 点 | 1008 点 |
| ZTE | 15 分钟 | 96 点 | 672 点 |

若选择 1 小时分辨率，则同样 7 天 = 168 点；界面同时显示“选中时间点（重采样后）”和
“原始采样间隔”，避免把 1008 误当成固定时长。

### 1.5 地图时间截面与分析范围

* 时间截面滑块的定义域被限制在**当前分析范围**内：`min = range.start_index`，
  `max = range.end_index - 1`。
* 范围变化时（例如把起点从 11-01 改到 11-02），若原截面落在新范围之外，会自动夹紧到
  `range.start_index`，并立即用该索引刷新地图；因此地图时间**不会早于分析起点或晚于终点**。
* 首次计算完成时，截面默认停在分析范围的第一个时刻。
* 截面仍然只影响地图与 Spatial Analysis，不参与右侧统计与自动结论。

### 1.4 校验规则（前后端一致）

| 代码 | 级别 | 条件 |
|---|---|---|
| `INVALID_DATETIME` | Error | 日期无法解析 |
| `DATE_ORDER` | Error | 开始时间 ≥ 结束时间 |
| `OUT_OF_BOUNDS` | Error | 范围完全落在数据边界之外 |
| `NO_POINTS` | Error | 范围内没有任何时间桶（例如 10 分钟数据里只选 00:05–00:09） |
| `TOO_FEW_POINTS` | Error | 只有 1 个时间点，无法做时间分析 |
| `TRUNCATED_START/END` | Warning | 部分超出边界，已截断到真实边界 |
| `SHORT_RANGE` | Warning | 跨度不足 1 天：日内规律与工作日/周末比较代表性有限 |
| `LAG_BELOW_DAY` | Warning | Max Lag 覆盖不足 24 小时，无法检查日周期 |
| `LAG_CLAMPED` | Warning | Max Lag 超过可支持范围，计算时截断 |
| `DAY_RANGE` | Error | 白天起始小时 ≥ 结束小时 |

错误显示在对应输入框下方并阻止提交；警告不阻止提交。

## 2. 统一计算范围

一次分析请求只解析**一个**范围，以下内容全部来自同一份 `values` 切片：

* Traffic Time Series 与 Statistical Summary（均值 / 最大 / 最小 / 标准差 / P95 / CV / 零值 / 有效点数）；
* Hourly Profile 与 Hourly Pattern Insights；
* Weekday vs Weekend 曲线与 Insights；
* ACF、趋势与 ACF & Trend Insights；
* Spatial Analysis 的 `range_mean`（逐区域在范围内均值）。

**例外**：中央 GIS 的“时间截面”滑块只决定地图显示哪一个瞬间（`time_index`），
不会改变上述统计；`Spatial Analysis` 的排名/分布基于该瞬间，`range_mean` 基于分析范围。

中央的多区域统计表逐区域独立计算（每行一个区域，互不混合）；右侧的 Hourly / Weekday / ACF
只针对 `insight_region_id`（Analysis Target）这一个区域。切换 target 不会重算或改变中央统计。

缺失值处理：`np.isfinite` 判定，缺失点不参与任何聚合，也不会被当作 0；ZTE 的真实 0 参与统计
（并在“零值”列计数）。

## 3. Hourly Profile（日内小时画像）

对小时 h = 0…23：

```
mean_h = mean(values[t] for t where isfinite(values[t]) and hour(t) == h)
samples_h = count(同上)
```

* 无有效观测的小时：`mean_h = null`，图表断点显示（No Data），不补 0。
* Tooltip 显示小时、平均值、有效样本数。
* 该图是“所选范围内跨日期的典型小时模式”，不是某一天的原始曲线。

### 3.1 Hourly Pattern Insights 规则

| 结论 | 计算 |
|---|---|
| 主要高峰 | `argmax(mean_h)`；若有多个小时与最大值相差 ≤1e-9·max，全部列出并标注“并列最高” |
| 与平均的差异 | `(max - mean_all) / mean_all × 100%`（均值为 0 时不显示百分比） |
| 主要低谷 | `argmin(mean_h)`，并给出与峰值的绝对差与相对降幅 |
| 日内模式 | 对 24 小时曲线做 3 点**圆周**平滑；局部极大值需同时满足：相对全天小时均值 ≥ +3%，局部突出度 ≥ 日均值的 3%，与相邻候选相距 >2 小时（否则合并，取原始值最高者）。0 个 → “整体较平稳”；1 个 → “单峰型”；≥2 个 → “多峰型” |
| 昼夜差异 | 白天默认 06:00–17:59（可在高级设置改），夜间为其余小时；比较两组小时均值，相对差异 <3% 时说明“差异很小”；分母为 0 时不输出百分比 |
| 数据可靠性 | 有效日期 <2 → 低；<7 → 中；某小时样本 <3 或小时覆盖率 <70% → 提示/升为中等 |

展开详情给出：有效点数/天数、小时覆盖率、全天均值、平滑与峰值阈值、昼夜划分。

### 3.2 Statistical Summary Insights（中央多区域）

| 结论 | 规则 |
|---|---|
| 平均流量对比 | 在**有有效观测**的区域中取均值最高/最低者，给出数值与相对差（以较低者为分母；为 0 时不输出百分比） |
| 波动程度 | 按 CV 的最大/最小区域给出数值；CV = 标准差 ÷ 均值 |
| 高位水平（P95） | P95 最高/最低区域与相对差 |
| 单区域 | 只有一个有效区域时只输出该区域的均值/极值/P95/CV 描述，并提示“如需区域间比较请再选择区域”，不生成排名 |
| 可靠性 | 无有效观测的区域排除并计数提示；覆盖率 <50%（<20% 降为 low）、样本量差 ≥4 倍时给出提示 |

表格下方固定显示：数据源、参与区域数、实际时间范围、每点分钟数、有效样本区间、单位。

## 4. Weekday vs Weekend

分组：周一–周五 = Weekday，周六/周日 = Weekend；组内按 0–23 小时求平均，并记录每小时样本数。
有效日期数按“该组内至少有一个有效观测的自然日”计数（不是按日历天数推断）。

### 4.1 特殊情况

| 情况 | 行为 |
|---|---|
| A 两组都有数据 | 正常出两条曲线与全部结论 |
| B 只有工作日 | 周末曲线全为 No Data；Warning：范围内无有效周末数据，不做完整比较；**绝不借用范围外周末** |
| C 只有周末 | 同理，工作日全为 No Data |
| D 某组只有 1 天 / 样本少 | 仍计算，但可靠性降级并提示 |
| E 两组都没数据 | 空状态 + 原因，不生成曲线 |
| F 部分小时缺失 | 对应小时保持 No Data，不填 0 |

### 4.2 Insights 规则

| 结论 | 计算 |
|---|---|
| 整体差异 | 分别给出两组样本加权均值；百分比差异使用**共同小时口径**（两组都有数据的小时，各自先求小时均值再平均），避免采样覆盖不均衡造成偏差。分母为 0 → 不输出百分比并明确说明 |
| 高峰时间 | 各组 `argmax` 小时；时间差按一天内最近距离 `min(|a-b|, 24-|a-b|)` 计算；缺一组时说明“无法比较” |
| 最大时段差异 | 只在两组都有数据的小时上找 `|weekday_h - weekend_h|` 最大者，给出小时、两组值、差值与哪组更高 |
| 形态差异 | 共同小时 ≥8 且两组方差 >0 时计算相关系数 r；r≥0.8 形态相似，0.4–0.8 有一定差异，<0.4 差异明显（仅描述形态，不推断活动目的） |
| 可靠性 | 组内有效日期 <2 → 低；<4 → 中；两组样本量比 ≥4 → 提示覆盖不均衡 |

## 5. ACF（自相关）与周期检测

### 5.1 计算

对滞后 k = 1…Max Lag：

```
ACF(k) = PearsonCorr( {v[t] : t 与 t+k 都有效}, {v[t+k] : 同上} )
```

* 逐对使用有效样本，**内部缺失不会把不等间隔数据当成等间隔**；每个 lag 记录有效配对数量。
* 95% 置信带使用白噪声近似：`±1.96 / sqrt(有效配对数量)`，图中以灰色虚线显示；这是近似判断带，
  不等同于严格显著性检验。
* 图上保留 ACF=0 参考线；Tooltip 显示 Lag、换算后的真实时长与 ACF。

### 5.2 Max Lag

| 采样 | 1 小时 | 24 小时 | 7 天 |
|---|---:|---:|---:|
| 10 分钟 | Lag 6 | Lag 144 | Lag 1008 |
| 15 分钟 | Lag 4 | Lag 96 | Lag 672 |

* **Auto 模式（0）**：数据覆盖 ≥2 周取“一周滞后 + 10% 余量”（10 分钟数据约 1109），
  ≥2 天取“日滞后 + 10% 余量”（约 158），否则取约 1/4 序列长度；最多 5000。
  余量用于观察候选周期之后的下降段，否则峰值无法确认。
* **手动模式（≥2）**：必须 ≤ 当前序列的 `点数-2`，超过时前后端都返回字段级 Error
  （`LAG_TOO_LARGE`），不会静默截断；输入 1 会返回 `LAG_TOO_SMALL`。
* 界面始终显示**实际生效值**（步数与换算时长），Auto 与手动明确区分。

### 5.3 周期检测

1. 先对序列做**线性去趋势**（避免长期趋势造成伪周期），再计算成对 ACF。
2. 候选周期：1 小时、24 小时、7 天（按采样间隔换算 Lag）。
3. 候选 Lag 的 ±5% 邻域内寻找局部 ACF 峰值；峰值与候选周期偏离 >20% 视为“不是该周期”。
4. **候选（candidate）** 需同时满足：
   * 峰值 ACF ≥ **0.25**
   * 局部突出度（峰值 − 邻域最小值）≥ **0.05**
   * 有效配对 ≥ **30**
   * 观测跨度 ≥ **2 个候选周期**
   * 峰值必须是**真正的局部极值**（左右相邻 lag 不高过它）；单调下降段不算峰。
   * Max Lag 必须至少到“候选 lag + 10%”，否则无法确认峰值，返回明确原因。
5. **确认（confirmed）** 还需同时满足：
   * 至少 **3 个完整重复**（`跨度 / 周期 ≥ 3`）
   * 该滞后处的有效配对 ≥ **2 × Lag**（保证足够重叠样本）
   * 峰值 ACF ≥ **0.4**
6. 只有 `confirmed` 会写成“已确认的周期证据”；`candidate` 会写成
   “候选周期，证据尚不足以确认”，并列出缺少的重复次数/配对数/峰值。
7. 可靠性：确认且峰值 ≥0.5、重复 ≥4 → high；确认但较弱 → medium；候选或不足 → low。

**局限**：ACF 峰值只说明“相隔该时长的取值相似”，不等于因果关系；短数据、强趋势、强缺失都可能
削弱或伪造周期信号，因此结论必须结合样本量与置信带阅读。

### 5.4 ACF & Trend Insights 条目

| 条目 | 规则 |
|---|---|
| 短期相关性 | 取前 2% 的 lag（至少 1–3）的 ACF 均值：≥0.6 强、0.3–0.6 中等、0–0.3 弱、<0 轻微反向 |
| 相关性衰减 | 把可用 lag 分四段，比较首段与末段均值；下降 ≥0.2 为明显衰减，回升 ≥0.2 提示周期结构；并报告最低点与之后是否回升 ≥0.25 |
| 负相关 | 全局最小 ACF ≤ −0.2 时报告 lag、真实时长与数值，并说明“不代表流量为负” |
| 潜在周期性 | 见 5.3；已确认与候选分开表述；无候选时给出无法判定的原因 |
| 线性趋势 | 见第 6 节 |
| 建议 | 仅在与当前情况相关时出现（Max Lag 不足、跨度不足、样本少、无周期信号） |

## 6. Trend（线性趋势）

对有效观测做最小二乘直线拟合：`value = intercept + slope × index`。

* 每点斜率按采样间隔换算：`slope_per_hour = slope × 60 / interval_minutes`，`slope_per_day = slope_per_hour × 24`。
* 方向：日均变化相对均值 <0.5% → “没有明显线性趋势”；否则为上升/下降。
* 额外要求 R² ≥ 0.05 才给出方向性表述；R² <0.3 时明确提示“拟合解释力有限”，避免把噪声当趋势。
* 中心时间序列图对分析对象绘制橙色虚线拟合线（仅该区间）。
* 结论始终注明“只描述所选区间，不代表未来走势”。

## 7. 图表与结论的一致性

* 一次请求返回同一份 `range + series + statistics + hourly + weekday + acf + trend + insights`，
  前端整体替换，避免“图表已更新、文字还是旧数据”。
* 参数变化后旧结果变暗并显示“正在按当前参数重新计算…”，加载中不把旧结论当作当前结论。
* 自动结论的每一条都附带 `metrics`（真实数值）；展开详情展示有效样本、覆盖率、阈值与方法。
* 多区域时，图表可对比多区域，自动结论针对“分析对象”（可在右侧切换），并在标题旁标明。

## 8. 已知局限

1. 周期检测基于自相关，不等同于谱分析或因果分析；结论以“候选周期/证据”表述。
2. 线性趋势对非线性、强周期数据解释力有限，R² 已在界面显示。
3. 工作日/周末比较需要范围内同时存在两类日期；只有一类时不会伪装出另一类曲线。
4. 单位：Milano/Trentino 物理单位未证实、ZTE 为 4G 下行流量，因此结论只描述数值变化，不解释为车辆数或出行目的。
